# The first PR run marks only the sessions set aside to wait

- **Date:** 2026-10-29
- **Area:** [Reading sessions](../architecture/sessions.md#reading-sessions)

## Decision

The first run, with nothing ever kept and the setting on, marks only the sessions with a tab or a later mark whose PRs already need you by that answer, the ones set aside to wait.

## Why

On the PRs linked 2026-10-29, 78 sessions had every PR merged or closed, 72 of them with neither a tab nor a later mark, most untouched for over a month, which is the pile of sessions done with but never marked finished, and not news.

## Turned down

- Marking every session already needing you at the first run: it would mark that pile.
